现如今，随着互联网技术的不断发展，源源不断的小厂开始崛起，像腾讯这样的老大哥也下场发福利，这不，腾讯云新出的EdgeOne边缘安全加速平台激励计划，激活码竟然还不限量！
官方目前提供了三种获取方式，个人感觉第一种更加快速简单

  1. 方式1：在X(Twitter)平台发布一篇推文,其内容包括

    • 话题标签：#EdgeOneFreePlan
    • 提及官方账号：@TencentCloudEO
    • 活动链接：https://edgeone.ai/redemption?from=recommend
      个人建议此方案将X的推文字数写满，获得几率更高哦！并且在发表完推文后，可以直接私信发给官方，一般第二天就会给你下发激活码啦

  2. 方式2：Discord抽奖

    • 加入官方频道：https://discord.gg/dGyw3VUe2U
    • 周一至周五的15:00/18:00/21:00（UTC+8），点击#giveaway频道中的链接参与赢取兑换码
      个人感觉此方法比较吃运气，但是好处是没有X账号的用户也可以获得，但是需要提前加入频道，并且需要等待时间

  3. 方式3：GitHub 合作计划

    • 参与 GitHub 开发者合作计划，即有机会获得免费套餐兑换码
    • 详细介绍：https://edgeone.ai/zh/blog/details/github-developer
      此方法我没有试过，但与前两种方式相比感觉会很难

实际体验

腾讯因为是中国大陆本土企业，所以在国内的节点数量还是蛮多的大概五十多个节点，足以使国内访问如同坐火箭一般迅速了

现在我的博客已经正式接入EO了！由于我的网站拥有ICP的备案，所有可以选用全球加速服务（包含中国大陆可用区），根据ITDOG和ZHALEME的测试，可以发现效果十分可观

在访问量增加起来之后基本可以做到全国深绿
另外对于中国联通的优化比其余两网更加优秀

当然，在我刚开始配置EO的时候并不是一帆风顺的，经过了我多次提交工单，也没有一个很好的解决方案，问题依旧
腾讯云的工作人员和我说，在CDN边缘节点与我的源站进行SSL握手的Finish阶段，握手就会被中断，导致无法正常建立TCP链接，进而导致访问加速域名时报错HTTP ERROR 525
腾讯云工作人员甚至使用腾讯的服务器手动测试了连接，根据日志显示确实在Finish阶段中断了握手，于是我便去找了阿里(源站服务器)的工作人员，但根据我自己和阿里工作人员的排查，握手不存在任何问题，每次测试都会返回0(ok)结果，访问网站也是HTTP 200(ok)，于是便不了了之，取折中方案，CDN节点与源站通信使用HTTP协议
在这里提醒各位，如果涉及到服务器与CDN跨厂商对接，可能会出现莫名其妙的问题，请务必注意

这里可能会有人担心使用HTTP协议是否会有安全隐患，我个人认为
服务器由自己管理，CDN 边缘节点由大厂管理，不会存在流量被劫持的风险，所以这个折中方案是比较妥当的。不过需要说明的是，HTTP 回源虽避开了 SSL 握手问题，但相比 HTTPS 回源少了传输加密环节。不过由于回源链路仅存在于 CDN 节点与源站之间，且在大厂节点防护下，数据传输安全性仍有保障，普通静态博客内容无需过度担心隐私风险，对访问体验也没有明显影响

这里十分感谢大佬清羽飞扬对EO配置的技术支持！
大佬的文章https://blog.liushen.fun/posts/68b52a49/

对于EdgeOne我并没有过多的研究，仅仅为其配置了一个缓存规则与访问规则，具体内容还是以官方文档为主！
对于静态博客，使用EO的默认缓存规则即可
我的自定义设置仅开启了



这几个功能，默认均为关闭功能
具体实际功能请以自己说需要的按需开启即可

总结

在这几天的配置和体验下来，总体还是非常简单的，EO自带的缓存模板已经足够大部分静态博客的需求了，不需要自己配置太多
如果你使用http回源，仅需配置一下加速域名和回源IP即可，等待5-10分钟后站点即可正常访问

在腾讯云的推动下，希望在互联网中，各位站长的建站成本可以逐渐的降低，让更多有兴趣的人可以加入进来

总结来说，各位新人站长、开发者，都可以以零成本或极低的成本来搭建小型的网站，以前高昂的成本已不复存在了！
